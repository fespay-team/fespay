## 管理方法

文書は原則Markdown、図はMermaidなど編集可能な形式を使います。画像・PDFは同階層のassetsへ置き、編集元と対応を記載します。外部資料は版・参照日・閲覧権限を記録します。秘密情報や本番の個人情報を含む証跡はコミットせず、アクセス制限のある保存先への参照を残します。

設計書は安定した入口から参照し、変更履歴をGitで管理します。移動・分割する場合は索引と相対リンクを同じPRで更新します。要件書は現行本文を維持し、受領時点/過去版はGit履歴から再現し、改訂ごとの全文コピーを作りません。

設計の状態は下書き→レビュー中→採択済み→廃止。採択記録にはPR・対象headの承認者・マージ日/commitを揃えます。実装の完了、受入合格、公開判定は別の証拠で記録します。実際に承認されたPRがない初期方針を、後続の文書同期だけで承認済みにしません。
