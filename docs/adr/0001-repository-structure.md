- 状態：初期構成へ適用済み。PR #1に個別APPROVEDの記録はない。固定workspaceは後続ADR-0005 / PR #15で採択済み。

## 背景

要件書はFE2人・BE2人・総合1人の5人編成を想定しています。
金銭処理・在庫・注文を整合させ、UIとAPIの契約変更も同時に確認する必要があります。
当初の対象はチーム開発用リポジトリの準備だった。現行はPR #17でnatuki53が役割枠を兼任し、開発基盤と認証の部分実装を行っている。

## 判断

当初はOrganization所有の単一privateリポジトリを提案した。現行はPublic（[設定記録](../team/github-setup.md)）。単一リポジトリの方針を維持する。
要件・設計・試験・運用を `docs/` に置き、将来のコードと同じPRで変更できるようにします。
初期の成果物は文書とコラボレーション用ファイルだった。

## 比較と影響

FE・BE・文書の別リポジトリは権限やリリースを独立させやすい一方、契約変更が複数PRに分かれます。
初期の5人開発では同じ変更を一度にレビューできることを優先します。
規模拡大で分割する場合は依存関係とデプロイ境界を再検討します。
現在のCIは全workspaceと設計/DB/認証を確認する。パスによる実行範囲の最適化は未採用。
