## 目的と対象

ローカルの `practice` 作業フォルダーで作成した、学園祭・地域のお祭り向けスマートフォン画面の操作例を記録する。React、TypeScript、Vite によるフロントエンドのデモで、ソースコードはリポジトリ直下の [`prototype/`](../../prototype/) に配置する（[PR #25](https://github.com/fespay-team/fespay/pull/25)）。現行の要件・設計を変更または承認する文書ではない。

## 画面と操作

| 画面 ID | プロトタイプで操作できる内容 |
| --- | --- |
| U02 イベント案内 | サンプルイベントの詳細表示。 |
| U04 イベントホーム | デモ残高カード、カード裏面の支払い用デモ QR、チャージ・送金・履歴・出店への導線。 |
| U05 支払い | 大きな支払い用デモ QR、現在のデモ残高、QR スキャン画面のサンプル表示。 |
| U06 チャージ | 来場者の受付用デモ QR、スタッフによる照合チェック、金額入力、現金受領チェック、完了票。確定後にデモ残高と履歴を更新。 |
| U07 譲渡 | サンプルアカウントの選択、金額と任意メッセージの入力、送金内容の確認、完了票。送る側と受け取る側のデモ残高・履歴を更新。 |
| U08 商品・カート | 出店一覧のサンプル表示。商品・カート操作は含まない。 |
| U10 履歴・問い合わせ | デモ取引を店舗名・相手・取引 ID で検索し、種類別に絞り込み、詳細を表示。問い合わせ操作は含まない。 |

マイページではサンプルアカウントを切り替え、送金の受取側の残高と履歴を確認できる。確認画面を経てデモデータを初期化できる。お知らせもサンプル表示である。

## 主な操作フロー

### チャージ

1. ホームから「チャージ」を開き、来場者の受付用デモ QR を表示する。
2. スタッフによる照合、金額入力、現金受領を画面上で順に確認する。
3. デモ残高と履歴を更新し、完了時刻と取引 ID を表示する。

### 送金

1. ホームから「送る」を開き、サンプルアカウントから相手を選ぶ。
2. 1 円以上の整数の金額と任意のメッセージを入力し、確認画面で相手と金額を確認する。
3. 確定後、送る側の残高を減らし、受け取る側の残高を増やす。双方にデモ履歴を追加する。
4. マイページで受取側のサンプルアカウントに切り替え、残高と履歴を確認する。

残高を超える金額は入力段階でエラーを表示する。メッセージは 50 文字まで。画面内で確定操作の連打を抑止する。

## データと実装の境界

残高、取引履歴、選択中のアカウントは同じブラウザーの `localStorage` に保存する。イベント、店舗、お知らせ、アカウントはサンプルデータである。送金は同じブラウザー内のサンプルアカウント間でのみ成立し、他の端末や実在する相手には届かない。

バックエンド接続、本人認証、実際の現金受領・決済・払戻し、受取人 QR の読み取り、カメラによる支払い QR の読み取り、サーバー発行の期限付き QR には対応していない。画面上の QR は実際の支払い・チャージ・送金に使用できない。サーバー上の原子的な取引・台帳処理や結果不明時の照会も実装していない。

## 起動と確認

リポジトリのルートから次を実行し、表示されたローカル URL をスマートフォン幅のブラウザーで開く。

```powershell
cd prototype
npm.cmd ci
npm.cmd run dev
```

`prototype/` でのビルド確認には `npm.cmd run build` を使用する。2026-10-14 時点でビルドが成功し、ブラウザー上で送金、残高不足、受取側の残高・履歴、再読み込み後の保存、初期化を手動確認した。これは要件の受入試験や、実金銭処理の安全性・並行処理の検証を意味しない。

## 正式実装に向けた課題

現行の[要件定義書](../requirements/event_payment_requirements.md)と[基本設計書](./basic-design.md)に沿って、認証・権限、イベント参加、受取人照合、API、サーバー上の取引と台帳、QR の期限と再試行、結果照会、返金・払戻し、商品・注文、管理・店舗画面、および受入試験を設計・実装する必要がある。
