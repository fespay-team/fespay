## 目的・対象範囲

来場者向けU01〜U10の表示・入力・操作・遷移・確認・異常時対応を定義する。画面間の関係は [画面一覧・遷移図](screen-map.md) を参照する。画面内の一覧・詳細・確認・完了・問い合わせ・ダイアログに新しい画面IDは付与しない。

正式な画面設計成果物の下書きとして、[UI設計の案内](README.md) と [設計書テンプレート](../../templates/design.md) に沿って記載する。[要件定義](../../requirements/event_payment_requirements.md) を優先し、[基本設計](../basic-design.md) 第11〜13章の画面表・導線・横断規約と、[詳細設計](../detailed-design.md) 第10〜14・23章の状態・期限・未決事項を具体化する。API契約の補足は [API設計](../api/README.md)・[クライアント復帰設計](../api/client-flows.md) を参照する。

## 設計

### 画面共通の前提

| 項目 | 設計 |
| --- | --- |
| 本人・イベント・店舗の境界 | 本人の残高・取引・注文のみ表示する。口座は本人とイベントで一意。カート・商品・注文では店舗境界も確認する。画面の表示制御と別に、サーバーが各操作の資格を検証する（ROL-02、ROL-03、WAL-01） |
| 認証・参加 | 公開情報以外は本人認証・必要なイベント参加を確認する。金銭操作は確認済みメールを持つ有効アカウントに限定する。既参加者への条件再同意・参加パスワード再入力は強制しない（ACC-01、JOIN-01、JOIN-02） |
| 表示構成 | スマートフォン縦画面を基本とし、白背景のシンプルな構成を引き継ぐ。選択中イベント、店舗・相手、主要操作、結果状態が分かる表示とする。完成版の色・余白などの詳細は未決 |
| 狭幅・操作性 | 最小320CSS px・文字200%でも店舗・金額・確定操作を隠さない。主ボタンは44×44CSS px以上を基準とし、ラベル・フォーカス・キーボード・コントラスト・色に依存しない状態表示を確認する。WCAG 2.2 AAは評価基準であり、適合済みとはしない（UI-01、UI-04） |
| 金額・承認 | 円の全桁を表示する。業務上の金額上限を設けず、入力は正の整数・技術的表現1〜30桁。0円・負数・小数・指数等を拒否する。合計超過を丸め・分割・部分処理しない。承認時はイベント、店舗または相手、円金額、処理種別、商品があれば明細と明示的な確定操作を示す（MNY-01、MNY-02、UI-02） |
| 期間・設定 | イベント状態と操作ごとの期間・機能設定・停止状態を確認する。期間境界はサーバー時刻で開始を含み終了を含まない。表示中の古い設定を確定の根拠にしない（EVT-04、CFG-01、CFG-02、CFG-04、TX-02） |
| QR・期限 | 用途を区別し、余白・コントラスト・縦画面の収まりを確認する。QR、承認、見積、予約の残り時間と期限前警告を視覚・支援技術で認識できるようにする。QR表示・読取・通知は成立証明にしない（QR-02、QR-03、UI-03） |
| 更新・戻る | 入力中の値や選択中注文を更新で勝手に変えない。戻る・画面移動は金銭成立や取消を意味しない。処理中・結果確認中・現金交付中の強制再読込みをしない（UI-07、PWA-02） |
| 正本・最終確認時刻 | 通知は更新の案内として扱い、再接続・前面復帰時に正本を取得する。取得成功まで最終確認時刻を更新せず、通信不可・更新中を表示する。残高・決済結果2秒以内、注文5秒以内は通常時の反映目標で、達成済みとはしない（NET-02、NET-04） |
| 模擬表示 | デモではMOCK／DEMOを明示して別環境で提供する。本番の現金受領記録・利用者メールを資料に流用しない（UI-08） |
