## 認証と追加認証

匿名画面もauth/contextを取得し、事前認証CookieとCSRF/Originで登録・ログイン・再設定を保護する。ログイン成功でsession Cookieを設定しCSRF文脈を交換する。確認/再設定メールはアカウント存在有無で同じ受付応答。PWは15〜128文字、trimやUnicode正規化をしない。秘密の本文・Cookie・tokenを監査の差分や冪等結果へ保存しない。

Googleの開始時にLOGIN/LINK/REAUTHENTICATEを指定する。callbackでは保存state/nonceと同じ文脈に束縛し、検証済みsubから本人を特定する。LINK/REAUTHENTICATEは5minの検証済みフローだけを生成し、別の本人操作で単回消費する。メール一致だけの統合は拒否。本人の認証手段一覧にproviderと連携日時を返し、最後の有効手段を解除できない。

callbackのGETはブラウザー遷移用。成功時は302と必須Location（同一Originの許可ReturnPath）、Cache-Control: no-storeを返す。必要時だけセッションCookieを設定する。戻り画面はauth/contextや本人用Googleフロー照会から状態を取得する。[静的検証](validation/README.md)では、このGETの302契約を通常APIの2xx契約とともに確認する。HTTPクライアントやSDKでcallbackのJSON成功本文を待たない。

通常sessionは無操作7日/絶対30日。メール方式で登録済み因子のchallengeが発生したら、ログインAPIは202 LoginChallengeを返す。challenge完了前の文脈は金銭APIへアクセスできない。Googleログイン済みでも、チャージ/現金払戻し/購入返金は業務MFAを別に検証する。最大8h/無操作30min、特権操作はMFA確認から5min以内。TOTP30s/±1周期・再利用禁止、5失敗/5min後15min停止。回復コードは単回ハッシュで、再発行で旧コード全失効。

GoogleのみのTOTP登録をPW設定の強制に依存させない。PW identityがある時はcurrent_passwordを必要な登録/管理要求だけで検証し、基盤へ即時転送後破棄する。Googleのみの利用者には最近のGoogle再認証を要求する。これらのアダプター動作は採用版で検証する。因子と回復コードを両方失った場合のサポート手順は未決。

## イベント・参加

イベント作成は確認済み本人をownerにし、DRAFT・非掲載・公開参加・払戻しON・譲渡OFF・失効なし・モバイルOFFで開始。現金受付条件は開催期間から推奨値を生成する。一般一覧は公開案内ありかつ掲載中だけ。参加前の案内に公開連絡先・期間・払戻し/失効条件を返し、非掲載にはnoindexを付ける。

参加は条件版・同意・必要時PWを検証し、account/event一意で参加と残高0のwalletを一括作成。新規参加前にmembershipを要求しない。PW変更は新規参加だけに適用し、既参加者の残高を維持する。10回/10min誤入力後15min待機。退出は残高3区分・未完了注文/案件が0の時だけ。過去参加と本人履歴は保持する。

条件設定のPATCHは版付きの全設定を送る案。PWはKEEP/SET/CLEARで扱い、保存した秘密をGETで再表示しない。初回チャージ後の不利益変更を拒否し、有利な変更には理由と新条件版を保存。通常払戻し受付と精算専用受付は別の期間/場所/連絡先を持つ。返金専用額を通常払戻しOFFで拒否しない。

dashboardはMINE/SHOP/EVENTを分ける。本人用へ他者・イベント売上を返さず、業務集計は現在の専用権限を確認する。店舗/レジ設定は親所属・機能依存を検証し、主催者の禁止/必須を店舗の選択より優先する。

## 招待・権限・主催者交代

招待はアプリ内一覧とコピーURLを用意し、メールを補助にする。発行者は主催者または自店舗レジを招待する店舗管理者。現権限と主催者の許可範囲内だけ。256bit・72h・単回・ハッシュ保存。秘密のURLは発行/再発行で一度返し、再発行では旧未受諾URLを失効する。

受諾は確認済み宛先本人で行い、membership不要。発行者の現権限・現在の許可条件を再確認し、範囲不足を勝手に縮小せず再招待へ案内する。並行受諾は同じgrantに復帰。受諾後grantは元発行者と独立し、旧管理者の解除で受諾済みレジを連鎖解除しない。旧管理者の本人残高・他所属を残し、その業務アクセスと未受諾招待を失効する。

交代は旧ownerの最近の再認証＋特権MFAによる指名と、指定された新ownerの受諾を別操作にする。未受諾期間はownerを変えない。新ownerが参加前でも本人/指名/期限を検証して受諾でき、確定時ownerは1人。期限72hは提案値。

## 停止・完了・公開ゲート

EVENT/SHOP/SERVICEの緊急停止は独立。期間や店舗設定で迂回しない。新規金銭処理を止めても既取引照会・安全な受渡し・既現金交付の完了記録は続ける。主催者の精算専用再開で許可する価値移動を限定し、通常営業を再開しない。

completion GETは未解決件数と先頭100件/カーソルを返し、POSTは同じ正本と制御行をロックして再判定。残高・拘束・現金差異/案件・注文・返金・失効バッチを残してCOMPLETEDにしない。完了後の訂正は理由付き精算再開へ。

公開ゲートG1〜G5の責任者・証跡・確認/取消はプラットフォーム特権で記録する。実際の外部確認や試験を証跡にし、画面入力だけで適法性・性能・品質を認定しない。未完了ゲートでも開発/模擬試験は進められるが、実金銭受付を開放しない。
